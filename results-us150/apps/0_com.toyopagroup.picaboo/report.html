MEDIUMPLAT-03.keyboard_open_access · Custom keyboard with full network access: Snapchat

The bundled custom-keyboard extension sets RequestsOpenAccess=YES. If the user turns on Allow Full Access, the keyboard gets network access while it sees everything typed with it, in any app. iOS swaps in the system keyboard for secure (password) and phone-pad fields, so those never reach it. This is the classic keystroke-exfiltration capability; confirm the keyboard genuinely needs network access.

Vector
PLAT-03
Why this severity
A keyboard with Full Access sees everything typed with it in any app and can reach the network: it observes the person across apps (WP248 criterion 3) and what it sees includes electronic communications (criterion 4). iOS keeps password and phone-pad fields on the system keyboard. MASTG-TEST-0390 then asks whether the typed text actually leaves the device, which needs the extension's code.

MEDIUMSECH-01.allows_arbitrary_loads · App Transport Security globally disabled (NSAllowsArbitraryLoads)

ATS is turned off app-wide, permitting plaintext HTTP and weak TLS to any host. Traffic can be intercepted/modified on hostile networks.

Vector
SECH-01
Why this severity
NSAllowsArbitraryLoads removes the HTTPS floor for every domain, so any request the app makes over http:// or weak TLS can be read and altered on the path. Connections that use HTTPS stay encrypted, and the scan cannot say what, if anything, the app sends in cleartext, so confidentiality and integrity are scored low (convention point 2); the breadth - every domain rather than listed exceptions - does not change what is exposed per request.
